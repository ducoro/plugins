# 14-Platform Legitimate Channel Access Matrix

This plugin operates strictly through **three legitimate, platform-official channels**—never extract browser session cookies, call reverse-engineered private endpoints, or bypass login/CAPTCHA challenges:

1. **Connected Ducoro Core Connectors (Check First When Available)** — before asking the user to configure developer apps or falling back to UI operation, check whether Ducoro already has an active Connector for the target platform (`ducoro-cli mcp catalog list --json`, `ducoro-cli mcp catalog status <slug> --json`, `ducoro-cli mcp catalog tools <slug> --json`). When a connected Connector exposes the required read, publish, comment, or analytics tool, invoke it first while still enforcing Gate 2 approval and `engagement_guard.py`.
2. **Official Platform OpenAPI (`scripts/client.py`, Optional User-Owned Credentials)** — works on **12 platforms** when the user explicitly supplies official developer API keys / OAuth tokens in environment variables or needs deep endpoints not exposed by a Connector (e.g., YouTube Analytics v2 AVD/AVP reports, WeChat Official multi-day stats, or standalone non-Ducoro hosts).
3. **Universal Fallback — Official Browser / Ducoro Computer Use (All Platforms, Zero API Setup)** — the **single universal fallback** for **all social perception, trend browsing, publishing, engagement, and Studio analytics** across every platform whenever neither a Connector nor user-supplied API credentials are available—or when a platform feature is web/Studio-only (e.g., Xiaohongshu / WeChat Channels publishing, X Articles, personalized `For You` / `Following` feeds, cross-account replies restricted by API tier, or Studio-only CTR/impression dashboards). **This fallback applies uniformly to all platforms and does not need to be restated in every platform playbook.**

## Universal Computer Use / Browser Operating Guardrails

Whenever operating via Ducoro Computer Use or Official Browser Creator Studio:
1. **Explicit availability reporting**: Computer Use requires an unlocked desktop host with Computer Use enabled. Never silently skip scheduled checks or report `no_change` when the desktop is locked or Computer Use is unavailable—explicitly report blocked coverage.
2. **Verify account & clear stale drafts first**: Before typing or uploading from `drafts/<draft-id>/assets/`, verify the active logged-in handle matches `accountId` and clear any leftover draft left by an interrupted prior attempt.
3. **Original text vs. auto-translation**: Distinguish original page copy from browser auto-translation when reading back drafts, published posts, or comments.
4. **Pause on auth gates & read back before retrying**: Pause immediately for human sign-in, 2FA, CAPTCHA, and Gate 2 confirmation. If an action times out or is interrupted mid-flight, inspect the live page/profile before retrying so posts or replies are never duplicated; after publishing, read back the verified `publicUrl` and timestamp into `publish-log.jsonl`.

## Channel Selection Rule

1. **Ducoro Core Connectors first**: Check `ducoro-cli mcp catalog list --json`, `status <slug> --json`, and `tools <slug> --json`. If an active Connector exposes the needed read, publish, comment, or analytics tool, invoke it first (still enforcing Gate 2 approval and `engagement_guard.py`).
2. **Official OpenAPI `scripts/client.py` second (when user-owned keys exist)**: When the user has explicitly configured official developer API credentials in environment variables, run `scripts/client.py` (preview with `--dry-run` during setup; use `ducoro-cli media upload <path> --json` for Meta/Pinterest 5-hour URL relay).
3. **Universal Computer Use / Official Browser fallback third (everything else)**: When no Connector and no user API credentials exist—or when the target workflow is web/Studio-only (such as X Articles, CN Creator Studios, or personalized feeds)—use Official Browser / Ducoro Computer Use under the universal guardrails above.
4. Never attempt to bridge missing API tokens by scraping cookies from the browser.
